How it works · the architecture

Your click becomes a job; the real engine answers it

In plain words

The website never makes up a number. Each button sends a request; the server checks it, runs our verified code on a worker and streams progress back so the charts fill in while it computes. Finished answers are saved, so asking again is instant.

Under the hood

Flask API: POST /api/jobs returns a job id; GET /api/jobs/<id> gives status, progress, log and partial results; DELETE cancels. Two worker threads. Results cached on disk by job type + parameters + engine version. Plain Python 3 with NumPy, SciPy and Flask, no build step.

The build · proof, and how to run it

What's proven, and how to run it yourself

Run it

Unzip, then one command: ./run.sh (Windows: run.bat) → open localhost:8000. Python 3.10+; installs NumPy, SciPy and Flask itself.

Docker: docker run -p 8000:8000 arjuna · no server at all: lab/arjuna-lab.html runs offline in any browser.

Limits we state up front

Minimal STO-3G basis, so exact answers are still classical. Chip noise is simulated (depolarising, all-to-all). Built for a laptop demo, not public hosting. The port to IBM's tools is written but not yet run.
